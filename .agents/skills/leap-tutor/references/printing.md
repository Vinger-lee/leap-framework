# A4 打印工作流

1. 用 `get_print_materials(session_id, node_id)` 查找已保存的草稿。用户没有要求改稿或换题时复用它。
   缺稿或明确要求更新时，取 `include_source=True`，看实际课程 Markdown、教学点和学习证据。
   创作前读取当前 `get_teaching_delivery_policy()`。仅需打印时可在结课后读取资料和导出。
2. 写一份学习者打开就能独立读懂的讲义 HTML。先给具体问题，再解释首次出现的术语和符号。
   对每个核心方法给出完整例题，逐行说明发生了什么、为什么这样做、最后如何检验。指出会算错的地方，
   让学习者先做一个短自检，再给核对过程。最后由题目册承接独立应用。
   用有标注的静态图解释关系或变化。可用内联 SVG 或嵌入图片，颜色用于区分方法、易错点和自检，
   同时用文字、线型或图例保留含义。一起检查 HTML 与实际 PDF 的层级、配色和分页。
3. 根据讲义重新出题。保留核心覆盖，有学习证据时加练薄弱点并调节难度，无证据时按讲义递进。
   每题关联讲义的教学点，独立求解并核对条件、干扰项、解答和相邻题是否泄露答案。
   用 `save_print_materials(...)` 保存新版本。检查 `uncovered_point_ids` 并实测分页，避免在题目册写入对应答案。
4. 默认调用 `export_print_pdf(...)` 导出合订册。用户可指定讲义、题目、答案解析、方向或边距。
   向用户展示真实返回的文件路径。没有 Chromium 时按错误回执引导安装，已准备 HTML 的用户可通过浏览器离线打印。
5. 页面发来 PDF 请求且缺稿时，处理回执里的 `next_call`，按上述流程创作后重试同一导出条件，
   把最终 PDF 回执映射到原 `call_id`。离线课程包使用 `html_directory` 写出独立文件，
   让四个页面入口指向对应 HTML。保存和渲染成功只确认技术结构，Agent 负责图文和题目内容复核。
