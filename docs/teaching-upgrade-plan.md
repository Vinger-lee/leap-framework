# 全局教学交付升级实施与验收

> [!info] 参考资源
> 核心：MCP 教学交付规范、Obsidian 双链知识库。
> 拓展：教学脚手架、可交互过程可视化、形成性评价。
> 进阶：知识图谱前置依赖、证据驱动评估、跨学科迁移。
> 未核验的视频不列入学习资源。资源是检索建议，不代表观看或阅读完成。

目标：全部模块、全部现有示例、新增学科、所有 Markdown 与后续生成输出永久遵循详细教学、可视化、宽屏、完整 Obsidian 知识源与严格学习资源规则；验收后一次提交 Git。

关联：[[docs/content-quality]]、[[examples/_shared/leap-web-spec]]、[[examples/_shared/leap-bridge]]、[[README_CN]]。

## 架构与边界

中央 `teaching_delivery_policy.json` 描述每个教学点的前置补习、机制、完整步骤、例题、误解、边界、对比、练习与迁移，以及资源验证、视觉、宽屏、Markdown 全源要求。所有 MCP 返回值携带不可由会话模式取消的版本化交付规则；生成蓝图附带结构模板。宿主必须先实际阅读来源，再编写最完整 Markdown，派生精简 HTML。

Runtime 新增 `save_teaching_package` 保存正文对及其内容覆盖证据；结构校验不把自动检查包装成学科知识真实性证明。教学产物不能仅提交路径假装经过验证。独立仓库校验器检查全部 Markdown 双链及所有教学包；浏览器校验动态交互、大屏占用与手机溢出，CI 运行相同门禁。

Markdown 与 HTML 的关系按正文核对，不能比较代码字符数。HTML 教学正文必须在 Markdown 中得到覆盖，Markdown 还必须有额外原理、演算、反例或拓展；资源模块、基础知识与逐步教学均可定位。协议、架构、贡献等工程文档没有 HTML 对应物，仍使用合法 frontmatter、双链、提示与检索资源，并保持工程细节。

## 实施任务

- [x] 中央交付政策、完整 Obsidian 模板和统一宽屏网页规范；范围覆盖所有学科与未来生成。
- [x] 全部 MCP 回包永久附带政策；诊断、知识分解、教学、评估、迁移、复习、报告蓝图明确执行顺序。
- [x] Runtime 教学包登记与结构拒绝路径；拒绝浅薄正文、缺失 MD、缺步骤与无可视化策略；视频核验资料缺失时拒绝，资料真实性仍需宿主审校。
- [x] Python、数学、OSI、物理、逻辑五个示例深度重写、演示扩充、宽屏适配和完整知识笔记。
- [x] 概率统计、化学与基础电路新增示例，新增学科目录与模块知识依赖图。
- [x] 全部 Markdown 的 Obsidian 改造、真实根路径双链、双向索引、资源与专题扩写。
- [x] 所有示例的行为场景、宽屏与手机检查；Markdown–HTML 覆盖门禁与反例测试。
- [x] 单元测试、静态检查、浏览器交互、真实 MCP 教学包联调；安装包包含新增政策与学科资源。
- [x] 逐条审计用户七项要求，修复遗漏，将完整升级与第一章可复现配方纳入统一 Git 提交。

验收记录见 [[docs/quality-audit-2026-10-10]]。新增学科目录是扩展起点，不能把目录项等同于整门学科教材；结构门禁也不能保证任意宿主永不生成错误内容。

## 可验证验收依据

1. 工具真实目录与回包政策版本一致，政策不能被 exam_prep/core_only 等会话模式省略。
2. 教学包校验对缺任一必备教学章节、视频验证资料不足或 MD 内容覆盖不足返回具体错误；正确包持久化双方正文和来源关联。
3. 每页有可操作的过程图示、分步控制、核心/变式题与完整说明；每页对应 canonical knowledge.md 比 HTML 教学正文更完整。
4. 1440/1920 PC 内容容器至少使用 88% 可用宽度、2560 下最大宽度 1800；375px 手机无横向溢出，键盘与减弱动画仍可使用。
5. 全部 Git 管理的 Markdown 有合法 frontmatter、真实可解析双链和返向链接；没有孤立文件或失效本地引用。
6. 未核验视频不在资源模块出现；缺核验时提供主题精确的三层检索词。
7. 原桥接 API、原始作答、提示级别、Runtime 状态权威性不回退；自由文本不关键词判分。

> [!warning]- 验证解释
> 结构与字数门禁只能拦截已知薄弱形态，不能证明所有学科命题。真实内容须依据来源、完整解题与边界反例审查；浏览器场景须触发实际路径，不能仅检查按钮存在。
