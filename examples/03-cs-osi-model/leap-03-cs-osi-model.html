01 · TEACHING · 教学内容

OSI 七层模型：职责、边界与跨网封装

从“为何分层”出发，能描述七层职责，区分 MAC、IP、端口，并沿着“主机 → 路由器 → 主机”解释数据单元如何变化。

建议 35–50 分钟 · 先读先修概念，再操作动画，最后完成递进练习

LEARNING RESOURCES · 搜索关键词

核心 / 必看：“OSI 七层模型 每层职责”“TCP IP 与 OSI 区别”“MAC IP 端口 区别”“计算机网络 封装 解封装”。

拓展 / 辅助：“以太网 帧头 帧尾 FCS”“路由器 每一跳 MAC 地址 TTL”“HTTP TCP IP 分层 Wireshark”。

进阶 / 深入：“ISO IEC 7498-1 OSI reference model”“RFC 1122 Internet layers”“RFC 791 TTL”“RFC 9293 TCP”“QUIC UDP TLS layering”。

这些是可复制到 B 站、课程平台或搜索引擎的检索词，不是已核验的视频推荐。优先选择能完整演示两跳封装并说明模型边界的材料。

先修：先认清“数据、地址、协议”

比特 bit是 0 或 1；8 bit 构成 1 byte。协议规定消息格式和处理规则，服务是某层向上一层提供的能力，接口是同一主机上下层交换数据的方式。两个对等层在逻辑上遵守同一协议，实际数据仍要通过下层和介质传送。

三种“送到哪里”

MAC：典型以太网中，用于当前链路的帧转发。
IP：标识网络层源与目的，支持跨网路由。
端口：传输层交付到相应的通信端点；端口并非某个进程的永久身份证。

四种常见数据单元

应用数据：如 HTTP 请求。
TCP 段：TCP 头 + 载荷。
IP 数据报：IP 头 + 载荷。
链路帧：帧头 + 载荷 + 帧尾；UDP 通常称“数据报”，并不称 TCP 段。

1. 分层是职责模型，不是七个独立的程序

通信需要应用语义、数据表示、会话管理、端点交付、跨网寻址、链路传送和物理信号。OSI 用七层把这些职责拆开。每层可借助下层服务，为上层提供能力；这样能够按接口替换技术，并按职责排查故障。

“同层逻辑通信”与“上下层实际传递”同时存在。浏览器与服务器遵守 HTTP，HTTP 数据实际借助 TCP/IP 和链路传到对端。分层不会保证网络更快，也不要求每层都实现成独立模块。

点击七层 SVG，或聚焦后按 Enter，查看每层的职责、常见实例和不能据此推出的结论。

七层自下而上

物理、数据链路、网络、传输、会话、表示、应用。先认识职责，再看协议与设备的具体功能。

层解决的问题 / 常见实例边界：不能推出什么
L7 应用面向应用的网络服务与消息语义；HTTP、DNS、SMTP。“应用层”并不是用户界面；DNS 可借助 UDP 或 TCP，不因此改变其应用服务职责。
L6 表示表示语法、编码转换、压缩、加解密等职责。现实 Internet 不保证存在独立的 L6；TLS 常放在应用与传输之间，不能硬说所有加密都只在 L6。
L5 会话组织对话、会话建立与管理、同步等职责。应用登录状态、TCP 连接与 OSI 会话不是同一概念，实际会话职责常由应用实现。
L4 传输通信端点之间的传输；TCP 有序可靠字节流、流量/拥塞控制；UDP 保留报文边界。UDP 不提供 TCP 式重传和排序，但不保证更快；TCP 不提供应用事务成功或加密的保证。
L3 网络跨网逻辑寻址和转发；IP、路由器的 IP 转发功能。IP 是尽力而为，不保证交付、顺序或无重复；路由器通常不会为转发而剥除 TCP 头。
L2 链路一条链路上的帧、介质接入和检错；以太网 MAC、二层交换机。链路检错不等于端到端可靠；以太网技术和网卡也包含物理层功能，多层交换机可有 L3 功能。
L1 物理将比特映射为电、光、无线信号；编码、时序、收发器、介质。它不会额外添加“IP 头”或统一的“H1 包头”；网卡的 MAC 功能不属于纯物理层。

2. OSI 与 TCP/IP：不要强行一一对应

OSI 是七层参考模型；Internet 通常按应用、传输、Internet/网络、链路四层描述，教学也常把链路拆成链路与物理形成五层。OSI 的上三层职责往往由 Internet 的应用协议、库或程序一起实现。协议归层要先声明采用哪种模型和正在讨论的功能。

按功能判断：“网卡属于哪层”信息不足，因为网卡通常涉及 L1/L2；“网卡收发器把比特变成信号”可归 L1。“交换机属于哪层”要限定二层转发还是三层路由。“以太网属于哪层”也要区分帧/MAC 与物理规范。

3. 完整例子：100 字节 HTTP 数据跨两条以太网链路

假设已有 TCP 连接，发送一段 100 byte 的明文 HTTP 应用数据。为看清层次，采用 IPv4，无 TCP/IP 选项、无 NAT、无分片，无隧道；忽略建连、重传与确认包。两个地址均为文档示例地址。

  1. 应用：生成 100 byte HTTP 数据。TCP 不是“一条应用消息必定对应一个段”；这里只选取一个不分段的简化示例。
  2. 传输：加 20 byte TCP 头，含源端口 53000、目的端口 80、序号等，成为 120 byte TCP 段。
  3. 网络：加 20 byte IPv4 头，源 192.0.2.10、目的 198.51.100.20、TTL 64，成为 140 byte IP 数据报。
  4. 第一跳链路：目的不在本地子网，发给网关。加 14 byte 以太网头与 4 byte FCS，帧的源/目的 MAC 为 A/G1，总长 158 byte。
  5. 物理：把帧对应的比特编码为信号发送；不是在帧外再增加一个“H1 包头”。
  6. 路由器：处理入口链路帧，把 IP 数据报交给网络层；查目的 IP 的路由，TTL 从 64 到 63，更新 IPv4 首部校验和；为出口链路重新封装帧，MAC 改为 G2/B，重算 FCS。此假设下 IP 源/目的和 TCP 端口保持不变。
  7. 接收端：从信号恢复比特/帧；链路层检错和去链路信息，网络层确认本机交付并去 IP 头，TCP 按序号等处理后把有序字节交给目的端点，HTTP 才处理应用消息。

字节核对：100 + 20 = 120（TCP 段）；120 + 20 = 140（IPv4 数据报）；140 + 14 + 4 = 158（以太网帧）。本例按帧头到 FCS 计数；不计前导码/SFD 与帧间间隔。MTU 1500 通常限制的是以太网载荷，不是这里包含帧头/尾的长度。

4. 对比、误区与排错

  • 逐跳与端到端：路由器会替换当前链路封装；IP 地址在本例中保留，但 NAT、隧道等可改变外层地址，因此“IP 永远不变”过强。
  • 检错与可靠：帧的 FCS 检错不等于必然修复，IP 尽力而为，TCP 用确认、重传等提高字节流可靠性。最终应用交易是否成功仍由应用处理。
  • 可达与可用：网线正常不保证 DNS 正常；能 ping 通不保证 TCP 端口开放；TCP 建连成功不保证 HTTP 返回成功；排查证据应对应正在检查的职责。
  • 顺序与头部：封装一般向下，解封装向上；具体协议加哪些头尾、是否压缩/加密、是否分段由协议决定，不是“七层必有七个头”。

MODEL BOUNDARY · 模型边界

OSI 是参考模型；协议和设备可能跨层。TLS、QUIC、NAT、隧道、三层交换机都提醒我们：先描述功能，再谈归层。

WATCH THE ROUTER · 重点观察

第一跳 A/G1 → 第二跳 G2/B：MAC 帧封装改变。无 NAT 时端到端 IP 地址保留，但 TTL 和 IPv4 头校验和改变；路由器转发无需解包到 HTTP。

进阶：重新核对字节与逐跳地址

变式：应用数据改为 200 byte；TCP 头 20、IPv4 头 20、以太网头 14、FCS 4 byte。仍无选项、NAT、分片或 VLAN，帧长度计至 FCS。
