# Internationalisation (i18n)

**语言 / Language**: **简体中文** ｜ [English](i18n.en.md)

LEAP 是模型无关的，会被各种宿主 Agent 嵌入使用，所以**学习者与运维人员会读到的文本**不能硬编码成单一语言。

---

## 1. 范围：什么被翻译，什么不被翻译

| ✅ 已本地化 | ❌ 有意不本地化 |
|---|---|
| State Guard 拒绝原因 | 代码注释、日志、异常类型 |
| 领域自学校准提示文案 | 工具名、字段名、枚举值 |
| 学习模式名称与描述 | Policy 决策理由（内部审计用，英文） |
| 结业报告标题与小节名 | Bloom 层级内部标识（`apply` 等） |

原则：**面向人的文案本地化，面向机器的标识保持稳定。** 工具名、字段名、枚举值一旦翻译，宿主 Agent 的集成代码就会碎掉。

---

## 2. 使用

### 配置

```yaml
# config/default.yaml
locale: zh-CN
```

### 环境变量覆盖

```bash
LEAP_LOCALE=en python -m leap.server
```

### 解析优先级

```
config 的 locale  →  LEAP_LOCALE  →  LC_ALL / LC_MESSAGES / LANG  →  zh-CN（默认）
```

接受的别名（大小写与下划线不敏感）：`zh` / `zh-CN` / `zh_Hans` / `cn` / `中文` / `en` / `en-US` / `english`。

---

## 3. 在代码里取文案

```python
# 工具层（推荐）
msg = self.t("domain_grounding.notice")

# 其他地方
from leap.i18n import translator_for
translator = translator_for(cfg)
msg = translator.t("report.title")
```

`Translator.t()` 的兜底顺序是：**当前语言 → 默认语言 → key 本身**。所以缺一条翻译最坏情况是显示 key，不会抛异常。

---

## 4. 新增一门语言

1. 在 `src/leap/i18n.py` 的 `SUPPORTED_LOCALES` 里加上语言代码。
2. 在 `MESSAGES` 下新增同名目录，**键必须与默认语言完全一致**。
3. 如有常见别名（如 `ja` / `ja-JP`），加进 `_LOCALE_ALIASES`。
4. 跑测试：`pytest tests/test_i18n.py`。

测试会强制校验：

- 两份目录的**键集合完全一致**（缺一条就失败，防止漏出原始 key）
- **占位符一致**（`{name}` 这类变量不能在翻译里丢）
- 没有空字符串条目

---

## 5. 为什么没有用 gettext / Babel

P0 的文案量很小（几十条），且要求**零外部依赖、单文件可读**。一个字典 + 一个 `t()` 函数已经足够，并且让"两份目录键集合一致"这种约束可以直接写成断言。

如果将来文案规模上到几百条、需要复数形式或日期格式化，再迁移到标准工具链更合适 —— 那时 `Translator.t()` 的调用点可以保持不变。
