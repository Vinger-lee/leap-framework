# MCP tool reference

Generated by `python scripts/generate_tool_reference.py`; do not edit by hand.

74 registered tools. Order comes from `src/leap/runtime/profiles.py`; parameters and descriptions come directly from `src/leap/tools/`.

`full` exposes all 74 tools; `quickstart` exposes 35. Each entry lists the profiles that expose it.

## `start_learning`

Profiles: full, quickstart.

```python
start_learning(learner_id: str, topic: str, *, goal: str | None=None, target_depth: str | None=None, target_domain: str | None=None, target_outcome: str | None=None, time_budget: int | None=None, prior_knowledge: str | None=None, constraints: str | None=None, mode: str | None=None, allow_skip_domain_grounding: bool | None=None, reuse_existing: bool=True, force_new: bool=False, request_id: str | None=None)
```

Start a session, record its goal and pick a learning mode in one call.

Coarse equivalent of create_session + save_learning_goal +
set_learning_configuration. The response returns next_call - the next
tool to call - and, when domain_grounding_notice is present, you must
show it to the learner verbatim before the grounding stage starts.

By default an active session for the same learner and topic is resumed
instead of silently creating a second one (``existing_session=True``).
Pass ``force_new=True`` to deliberately start another session.

## `continue_lesson`

Profiles: full, quickstart.

```python
continue_lesson(session_id: str, node_id: str | None=None, *, verbose: bool=False)
```

Return the teaching state and the next action in one call.

Coarse equivalent of get_teaching_context + get_session_info. Reports
the policy engine's recommended strategy and actions together with the
evidence stage, friction signals, active misconceptions and due review
count, plus next_call. The facade never selects the pedagogy itself.

``verbose=False`` (default) returns the summary only; pass
``verbose=True`` to embed the full teaching context (or call
``get_teaching_context`` directly when you need it).

## `log_teaching_action`

Profiles: full, quickstart.

```python
log_teaching_action(session_id: str, *, action: str | None=None, strategy: str | None=None, node_id: str | None=None, rationale: str | None=None, expected_outcome: str | None=None, request_id: str | None=None)
```

Record the teaching action you actually took (section 27.1).

Coarse equivalent of commit_pedagogical_decision. Omitting action and
strategy records the runtime recommendation, so the decision log is
never empty; passing what you did keeps the log auditable.

## `submit_answer`

Profiles: full, quickstart.

```python
submit_answer(session_id: str, answer: str, *, item_id: str | None=None, node_id: str | None=None, hint_level: int=0, response_time: float | None=None, correctness: float | None=None, conceptual_understanding: float | None=None, reasoning_quality: float | None=None, application: float | None=None, transfer: float | None=None, hint_dependency: float | None=None, assessor_type: str='model', assessor_confidence: float=1.0, confidence: float | None=None, expected_state_version: int | None=None, request_id: str | None=None)
```

Record the learner's answer and commit your assessment in one call.

Coarse equivalent of submit_attempt + commit_assessment (plus a read-back
of the updated state). The raw answer is stored verbatim and reused as
raw_answer, which removes the usual mismatch error. With no score
supplied only the attempt is stored - use that when free-text reasoning
still needs your semantic review, then call commit_assessment yourself.
Never send mastery_probability: it is computed server-side.

## `advance_lesson`

Profiles: full, quickstart.

```python
advance_lesson(session_id: str, *, unit_tag: str | None=None, node_id: str | None=None, expected_state_version: int | None=None, request_id: str | None=None)
```

Dry-run the State Guard and advance only if it allows the transition.

Coarse equivalent of check_advance_unit + advance_unit. A rejection is
not an error: the response returns advanced=false, the guard's own
reason and the repair action, and nothing is written. Never work around
a rejection in prompt text - and the host has no manual_override switch
to do so with.

## `review_answer`

Profiles: full, quickstart.

```python
review_answer(review_item_id: str, rating: int, *, session_id: str | None=None, request_id: str | None=None)
```

Apply a 1-4 FSRS rating to a due review and reschedule it.

Coarse equivalent of submit_review. Rate what you observed: a rating of

## `set_domain_grounding_skip`

Profiles: full, quickstart.

```python
set_domain_grounding_skip(session_id: str, allow_skip: bool=True, *, warn_user: bool | None=None, reason: str | None=None, request_id: str | None=None)
```

Record the post-creation Domain Grounding decision (skip or require).

The grounding switches used to be write-once at ``create_session`` time,
so when the learner answered "skip it" after seeing the notice the host
had to throw the session away and create a new one. This tool lets the
decision be recorded on the existing session. Changing the switch does
not erase evidence; it only changes the gate for later tool calls.

## `advance_unit`

Profiles: full.

```python

```

Request the next unit.

Every node sharing the unit_tag must pass its own node-level guard;
one failure rejects the whole request. There is no unit table. On
success the focus moves to the next unit's entry node; when the last
unit is passed the result says so explicitly (``has_next_unit=False``)
instead of silently restarting the current unit.

## `save_teaching_package`

Profiles: full, quickstart.

```python
save_teaching_package(session_id: str, node_id: str, subject: str, markdown: str, html: str, manifest: dict, *, request_id: str | None=None)
```

Validate and store canonical Markdown and projected HTML with teaching records.

Supply actual complete bodies, resources, teaching_points, html_segments,
markdown_extensions and source_ids. New and revised visuals must declare
``visual_contract`` with profile ``anatomy.v2`` (research +
evidence_source_id links, parts/inspection and model checks); the full
schema is returned by get_teaching_delivery_policy. A brand-new teaching
package for a node is rejected unless it is anatomy.v2, the lesson is
text-only (every teaching_point has ``no_visual_reason``), or the host
explicitly opts into legacy compatibility with ``allow_legacy: true``
(recorded in artifact metadata and returned as warnings). For a v2
package every research ``evidence_source_id`` must come from the latest
completed save_benchmark_report and every ``checked_at`` must not be in
the future. ``source_ids`` must be the ``sources_saved`` ids from
save_benchmark_report (shipped example manifests contain a placeholder
that has to be replaced). Accepted records are structurally checked, not
semantically certified.
